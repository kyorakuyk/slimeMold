# SlimeMold 轻量界面研究稿

## 目标

为不熟悉节点编辑器的用户提供一条从自然语言目标开始的项目入口，同时保留现有 React Flow 主界面作为专业执行与调试工作台。用户不需要先理解节点、Agent 或 DAG；主控 Agent 通过有限的高价值问询，把一句话目标收敛为可确认的项目 Brief、架构和执行计划。

本轮方向调整会触及项目会话、Issue、Decision 和 Task 的数据模型，因此不再坚持“只增加一层 UI、完全不改变项目模型”的旧假设。执行器和 H4 宿主安全边界仍然复用现有实现，不为初级页面复制一套执行逻辑。

## 页面结构

### 初级页面：项目首页与主控会话（Intent / Project）

没有当前项目时，用户看到：

- 一句话目标输入框；
- 主动作“开始项目会话”；
- 打开已有项目和最近项目；
- 简短说明：主控会问询、整理方案，用户确认后才执行；
- 不直接强调高级工作台。

创建项目后，首页转为当前项目上下文，并显示：

- 项目名称、生命周期状态和本地工作区；
- 主控会话的下一步和未决问题；
- 当前理解、假设和已批准的 Decision；
- 最近 Issue、交付物、运行状态和需要用户确认的事项；
- 继续会话、查看 Issue、查看交付物和进入专业视图。

初级页面不展示节点、Provider、Token、MCP、Agent 绑定或 DAG 参数。用户看到的是目标、进度、风险、待确认事项和真实交付结果。

### 进阶页面：Issue 工作台（Planning / Change）

Issue 工作台是跨项目的变化入口，同时支持当前项目筛选。建议聚合为四个面板：

1. **收件箱 / 未规划**：未认领想法、Bug、风险和问题；不自动执行；
2. **待做**：已经批准并进入队列的任务；
3. **在做**：施工、验证、阻塞和等待人工确认的任务；
4. **已交付 / 运维中**：一次性交付结果和已经批准进入持续运行的项目。

“Issue”是对象类型，不是唯一状态。未认领 Issue 使用明确的 `projectId: null` 表示；标签只用于分类和筛选。主控可以提出归类到旧项目或新建项目的建议，但必须经用户批准。

### 专业页面：Workflow DAG（Execution / Inspect）

现有 React Flow 工作台继续作为专业用户的执行和调试界面。它负责节点级工作细节，不取代项目会话或 Issue 工作台。专业视图需要显示当前项目、关联 Issue/Task、Pipeline 阶段、运行状态、worktree、diff、测试和 Evidence。

Issue、Task Graph、Pipeline 和 Workflow DAG 不是复制关系，而是通过稳定 ID、来源版本和影响范围建立映射。专业用户修改接口、数据模型或模块边界时，应生成架构变更提案，而不是静默改写 PRD。

## 主控会话交互契约

主控会话不是无限聊天，也不是项目事实的唯一存储。它应当在每轮交互中展示：

```text
当前阶段：需求澄清 / 架构确认 / 计划确认 / 执行中
已确定：目标、约束、技术环境
仍需决定：会改变架构、成本、权限或验收的关键问题
系统建议：当前方案、假设、不确定性和预计影响
用户动作：批准 / 修改 / 暂不决定 / 停止
```

会话消息保留原始上下文；用户批准的内容提炼为 `Decision`，结构化方案保存为版本化 `Artifact`。初始确认门至少包括目标范围、架构与接口、任务计划、执行、合并/发布和持续运维。

## 视觉方向

这是 Apple-inspired，而不是 Apple UI 的复制：

- 使用 `-apple-system` / `Segoe UI` / 中文系统字体；
- 浅色表面使用接近 `#f5f5f7` 的暖灰，深色主题保持低对比黑灰；
- 交互主色只使用蓝色，类似 Apple Blue `#0071e3`；
- 使用大留白、清晰的显示级标题和有限的半透明材料；
- 卡片不依赖重边框，层级主要由背景、间距和轻阴影表达；
- 圆角控制在 12–20px，按钮保持至少 44px 高；
- 不使用外链图片、库存照片或 Logo 作为核心信息；
- 不使用彩虹色、霓虹渐变、伪造数据和装饰性指标。

### 组件语义

- 蓝色：可以操作的动作或当前选中状态；
- 绿色：真实成功结果；
- 黄色：需要注意或需要人工确认；
- 红色：真实失败；
- 灰色：尚未开始、辅助说明或不可用。

## 交互边界

- 无项目首页的主动作打开项目会话；旧的 `NewProjectModal` 可以作为项目元信息和落盘设置的一部分，而不是整个需求入口；
- 当前项目首页显示当前项目，不展示脱离上下文的空白高级工作台；
- 专业视图切换到现有画布，不复制一套执行逻辑；
- 主控生成的草案、Decision 和计划必须经过用户确认，才调用现有 Orchestrator/运行链；
- Issue 的归属、入队、执行、完成和运维状态由项目级数据模型驱动；
- 运行失败、架构漂移和运维事件可以生成关联 Issue，保留来源 Run/Evidence；
- 所有统计优先使用 store 和宿主真实记录，不生成虚假 KPI；
- 会话、Issue、Artifact 和 DAG 必须保留项目范围、版本和来源，避免页面之间各自维护一份真相。

## 后续验收

1. 新用户可以从一句话目标进入项目会话，不需要先配置空白 DAG；
2. 主控能持续维护当前理解、未决问题和用户 Decision，并在确认前不产生不可逆副作用；
3. 已有项目首页显示当前项目、会话下一步、Issue 和交付物；
4. 未认领 Issue 可以在用户批准后归入旧项目或建立新项目；
5. Issue、Task、Stage、Workflow、Run 和 Artifact 之间可以追溯；
6. 专业工作台打开的是当前项目，不是脱离上下文的空白画布；
7. 运行中的状态、成功、失败和需要确认不会被视觉混淆；
8. 浏览器预览和 Tauri 桌面端都不白屏；
9. `npm run build`、`npm run test` 和 `npm run i18n:check` 通过；
10. 文档明确区分已实现、设计中和仍未验证的能力。
